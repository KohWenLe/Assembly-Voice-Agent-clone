# Domain documentation

This repository currently has one product context: restaurant drive-thru ordering.

- Keep confirmed product requirements and open questions in [the requirements document](../product/requirements.md).
- Create a root `CONTEXT.md` when domain terms and their meanings have been settled with the team.
- Record significant, difficult-to-reverse architectural decisions in `docs/adr/` when selected. No such decision has been made yet.
- Keep proposals visibly separate from confirmed decisions. Missing glossary or ADR files do not block the requirements interview.

The [hackathon research brief](../research/2026-09-21-hackathon-requirements.md) holds the verified event constraints and their sources.
